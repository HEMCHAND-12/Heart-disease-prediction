# Heart Disease PaRSEL

Starter workspace for reproducing the paper's heart-disease stacking model with
feature reduction, class balancing, XGBoost, and SHAP explanations.

## Environment

The project is configured for a CPU-only Python virtual environment in `.venv`.
The laptop has 8 logical CPUs, approximately 7 GiB RAM, and Python 3.14.
Large oversampling experiments should be run one technique at a time to keep
memory use predictable.

Create or refresh the environment with:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
```

Activate it in a terminal with:

```bash
source .venv/bin/activate
```

The paper's reported results are research benchmarks, not clinical advice.

## Reproduction Status

The primary target is the `diabetes` label in
`data/diabetes_prediction_dataset.csv`. Its 100,000 rows and original 91,500 /
8,500 class counts match the data description in the paper. Do not merge
`data/cardio_train.csv`: it is a separate cardiovascular dataset with a
different target. The files named `diabetes_cleaned_all_features.csv` and
`diabetes_reduced_lda.csv` on the other branch are also excluded; their labels
were constructed from cardio glucose categories and LDA was fit before a test
split.

The previous committed ROS train/test pair is kept as an audit artifact, not
used for results. Its train and test rows share 1,091 exact duplicate records.
The new runner removes exact source duplicates before creating a fixed split,
then balances only each training fold. This changes the row count and class
ratio slightly; the paper does not specify a duplicate policy, split ratio, or
seed.

## Run Experiments

Install the pinned environment using the setup commands above. The complete
experiment entry point is:

```bash
make reproduce
```

This regenerates the seed-42 stratified 80/20 split, runs the full sampler and
reducer grid, then runs the prioritized grouped-split robustness checks and
creates the report. The sampler grid is large; run a smaller first pass with:

```bash
make reproduce-priority
```

That pass runs ROS with no reduction and the paper-prioritized ProWRAS + LDA/RFE
combinations, plus a train-only randomized search for the meta learner. The
grouped split can be rerun separately with `make robustness`; tests run with
`make test`.

The output is stored in `splits/` and `results/`. `results/config.json` records
seeds, split ratios, preprocessing policy, parameters, and library versions.
`results/all_runs.csv` is append-only and includes failed/unavailable runs as
well as metrics and timing. The report and plots are generated by
`scripts/report_results.py` and saved in `results/`.

## Method Choices and Limits

- Exact duplicate full rows are removed before splitting to guarantee no exact
	row crosses partitions. The secondary grouped evaluation also keeps equal
	predictor combinations together, including groups with conflicting labels.
- Missing rows are removed before splitting if present. Continuous outliers
	are capped at train-fitted 1.5-IQR bounds because the paper does not define
	its outlier rule. Encoders, scalers, reducers, samplers, and OOF base models
	are fitted on training data only.
- PaRSEL's named base learners are Passive Aggressive, Ridge, SGD, and XGBoost.
	`GradientBoostingClassifier(loss="log_loss")` is the documented LogitBoost-
	style meta-layer substitute; it is not claimed to be canonical LogitBoost.
- ROS, ADASYN, SMOTE, and Borderline-SMOTE use imbalanced-learn. ProWRAS,
	LoRAS, MWMOTE, and RWOS require `smote-variants`; they are marked unavailable
	if that package or an exact implementation is absent. No substitute is
	silently reported as the paper's method.
- Tables 3-11 contain rasterized classifier cells in the included paper PDF.
	The report compares rounded values stated in the paper's prose and does not
	invent missing cell values. Differences from paper results are reported, not
	tuned away.

The original logistic-regression reference remains available with:

```bash
.venv/bin/python scripts/baseline.py
```

This is a separate baseline and is not a PaRSEL reproduction result.

## Results Summary

The first interrupted run completed the standalone ROS/no-reduction models but
did not finish PaRSEL. On the fixed test split, standalone XGBoost reached
89.51% accuracy, 92.04% recall, 60.74% F1, and 0.9763 ROC-AUC; the
LogitBoost-style surrogate reached 92.36% accuracy, 86.14% recall, 66.55% F1,
and 0.9748 ROC-AUC. The positive class is only 8.82% of this test set, so these
accuracy values should not be read alone. Full metrics and all five completed
standalone rows are in `results/comparison_to_paper.md`.

These are not PaRSEL results. The PaRSEL stack, tuned variant, grouped-split
metrics, remaining sampler/reducer grid, ROC/PR curves for PaRSEL, and SHAP
plots remain unfinished. Do not cite the standalone values as reproducing the
paper. The report preserves the paper's 67% versus 70% recall discrepancy, its
separately reported tuned 98% accuracy / 97% recall, and the duplicate,
imbalance, and timing limitations.
