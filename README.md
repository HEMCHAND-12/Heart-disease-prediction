# Diabetes Risk Modeling: PaRSEL Baseline and PaRSEL+ Extension

B.Tech major project extending the PaRSEL stacking approach with stricter
evaluation, operating-threshold selection, calibration, subgroup analysis, and
external validation. Phase 1 is a leakage-safe baseline inspired by Noor et al.;
Phase 2 is the proposed PaRSEL+ framework. The base paper's title says heart
disease, but its primary 100,000-row dataset and target are diabetes.

## Environment

The project is configured for a CPU-only Python virtual environment in `.venv`.
The laptop has 8 logical CPUs, approximately 7 GiB RAM, and Python 3.14.
Large oversampling experiments should be run one technique at a time to keep
memory use predictable.

Create or refresh the environment with:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
```

Activate it in a terminal with:

```bash
source .venv/bin/activate
```

The paper's reported results are research benchmarks, not clinical advice.

## Project Phases

The primary target is the `diabetes` label in
`data/diabetes_prediction_dataset.csv`. Its 100,000 rows and original 91,500 /
8,500 class counts match the data description in the paper. Do not merge
`data/cardio_train.csv`: it is a separate cardiovascular dataset with a
different target. The files named `diabetes_cleaned_all_features.csv` and
`diabetes_reduced_lda.csv` on the other branch are also excluded; their labels
were constructed from cardio glucose categories and LDA was fit before a test
split.

**Phase 1: baseline.** The paper-faithful variant retains all 100,000 source
rows and uses a seed-42 approximately 80/20 stratified grouped split, with
identical predictor tuples kept on one side to avoid duplicate leakage. ROS and
other samplers are applied only to training rows. Separate deduplicated and
predictor-grouped variants are kept as robustness checks. This grouped split is
a deliberate leakage-control deviation because the paper does not specify its
split or duplicate handling.

**Phase 2: PaRSEL+.** Planned improvements are evaluated as ablations against
the completed Phase 1 baseline. No improvement is claimed until paired
statistical tests support it. The extension work is not represented as a copy
or reproduction of the paper.

The committed ROS pair remains an audit artifact: 1,091 exact records overlap
between its train and test files. It is never used for reported evaluation.

## Run Experiments

Install the pinned environment using the setup commands above. The complete
experiment entry point is:

```bash
make reproduce
```

This launches the checkpointed Phase 1 priority queue in the background, with
the paper-faithful variant first, then deduplicated and predictor-grouped
variants. Completed runs are appended to `results/all_runs.csv`; resume skips
existing run keys. Monitor progress with `tail -f results/phase1.log` and the
PID recorded in `results/phase1.pid`. Phase 2 targets will be run only after
Phase 1 priorities complete.

For only the primary variant:

```bash
make reproduce-priority
```

Priority order: ROS/no reduction (including standalone comparisons and tuned
stack), ROS+RFE, ROS+LDA, SMOTE+LDA, SMOTE+RFE, ADASYN+LDA, then ProWRAS+LDA/RFE
if available. The single isolated no-deps `smote-variants` install attempt
could not import because `metric-learn` is missing; those methods are logged as
unavailable, with no installation retry. Tests run with `make test`.

The output is stored in `splits/` and `results/`. `results/config.json` records
seeds, split ratios, preprocessing policy, parameters, and library versions.
`results/all_runs.csv` is append-only and includes failed/unavailable runs as
well as metrics and timing. The report and plots are generated by
`scripts/report_results.py` and saved in `results/`.

## Method Choices and Limits

- The primary split retains exact duplicates from the source but assigns equal
	predictor tuples to one partition. The deduplicated variant removes 3,854
	exact duplicate rows; grouped results are reported separately.
- Missing rows are removed before splitting if present. Continuous outliers
	are capped at train-fitted 1.5-IQR bounds because the paper does not define
	its outlier rule. Encoders, scalers, reducers, samplers, and OOF base models
	are fitted on training data only.
- PaRSEL's named base learners are Passive Aggressive, Ridge, SGD, and XGBoost.
	`GradientBoostingClassifier(loss="log_loss")` is the documented LogitBoost-
	style meta-layer substitute; it is not claimed to be canonical LogitBoost.
- ROS, ADASYN, SMOTE, and Borderline-SMOTE use imbalanced-learn. ProWRAS,
	LoRAS, MWMOTE, and RWOS require `smote-variants`; they are marked unavailable
	if that package or an exact implementation is absent. No substitute is
	silently reported as the paper's method.
- Tables 3-11 contain rasterized classifier cells in the included paper PDF.
	The report compares rounded values stated in the paper's prose and does not
	invent missing cell values. Differences from paper results are reported, not
	tuned away.

The original logistic-regression reference remains available with:

```bash
.venv/bin/python scripts/baseline.py
```

This is a separate baseline and is not a PaRSEL reproduction result.

## Results Summary

Current Phase 1 results and unsupported runs are summarized in
`results/comparison_to_paper.md`. The Phase 1 primary PaRSEL stack has a first
successful run on record; the baseline comparison is still in progress until
all prioritized variant runs finish. PaRSEL+ results belong in
`results/extension_results.csv` and `docs/final_report.md`, not in the Phase 1
baseline table. Results are reported without test-set tuning or cherry-picking.
